# Windows v1 feature freeze — local RC6

Status: feature freeze candidate on `codex/windows-tauri`. `main` is untouched. This is not a production release or Windows 10 certification. Further work is limited to defects, accessibility, acceptance evidence, licensing and release preparation unless the user explicitly reopens scope.

## Included scope

- Desktop Adhkar reading workspace with a separate counter panel and keyboard interaction. Shared progress/reset handlers; independently preserved mobile presentation. Romanized text is labeled Transliteration.
- Existing PDFium/EmbedPDF reader with desktop inactivity controls, keyboard/focus recovery, fit-width/page/actual-size actions and existing collapsible contents/thumbnails/bookmarks. Hiding chrome does not resize or rerender pages. Existing progress/storage identifiers remain unchanged.
- Build-generated canonical catalog, stable legacy IDs/URLs, preserved beginner order and cached files, desktop cards/folder explorer, sorting/search, and personal PDF previews/progress. Manifests are explicit build inputs, not browser directory scans or automatic remote imports.
- Signature (default), Classic, Slim and Countdown Focus layouts, independent of theme; existing ribbon remains available. Optional seconds preserved. Native semantic colors now resolve CSS color-mix values before transfer.
- Gentle Chime (default), Soft Bell, Wooden Tap, Digital Beep, Silent and Custom timer audio. Independent 0–100% volume. Custom files are decoder-validated, limited to 20 MB and stored only in the native profile. Built-in tones are generated by Sahib, with no new audio asset license/dependency.
- Al-Qatami standard/Fajr defaults for fresh preferences; saved selections remain unchanged. Religious calculations and scheduler policies are unchanged.
- Explicit regional method suggestions using existing methods, with an opt-in city-following setting. Existing method/madhab/adjustment choices remain intact unless the user applies a suggestion. Regional differences and Ramadan Isha require local verification. Iran/Shia guidance uses an authority timetable; no unsupported twilight-Maghrib calculation is claimed. References: [Adhan.js method guide](https://github.com/batoulapps/adhan-js/blob/develop/METHODS.md), [PrayTimes conventions](https://praytimes.org/docs/methods).
- Permanent localized Islamic greeting with smaller live time-of-day greeting, original reflective subtitle, prominent Arabic Names alongside transliteration/meaning, keyboard search, and restrained Tasbih spacing. Fresh accents use peach where supported, warm palette alternatives otherwise; existing theme/accent choices are preserved.

## Verification

- Rust unit tests: 20 passed, including scheduler, focus, missed-alert policy, timer persistence, native geometry and generated-tone sample bounds/fades.
- Actual isolated native Tauri checks: hidden Classic-to-Signature clipping transition, six theme color transfers, sound persistence, custom WAV/MP3 decoding, invalid-input rejection, four layouts, independent Adhan settings, and timer completion after main WebView destruction.
- Actual native screenshots reviewed at the current physical 125% scale: Classic/Signature, Arabic Slim and Countdown Focus. Earlier RC5 physical tests verified 150%/200% clipping correction and restored 125%; the new layouts have not each been physically tested at every DPI.
- Browser acceptance passes at 1280×720, 2560×1440 with 2× rendering and 390×844 mobile: localized/time-changing greeting, search keyboard navigation, session counting/layout, PDF fit actions, page/bookmark restoration, desktop view persistence and personal previews. A separate 1920×1080 PDF test also passed. Browser DPR testing is not an actual Windows DPI-setting change.
- All 70 legacy book IDs/file paths and 10 beginner entries are checked. Existing cached PDFs still open after the catalog gate. New unverified downloads are rejected; metadata browsing does not initialize PDFium for unavailable covers.
- Runtime packaging uses an explicit allowlist excluding tests, profiles and QA artifacts. No `Zurich memory fixture` default exists in application source/runtime. Saved user locations are not replaced.
- Real prayer-time Adhan, sleep/resume timer popup/chime, unlock recovery and Narrator were user-confirmed during the preceding Windows acceptance pass. Those confirmations precede the new sound/layout additions; they are not claims that every new tone has been listened to.

Repeatable checks: `node tools/verify-release.mjs`, `node tools/test-book-catalog.mjs`, `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib`, `node tools/verify-v1-widget.mjs`. For web UI checks, serve the workspace locally and run `tools/browser-smoke.mjs` with `@tests/desktop-ui-acceptance.js` in an isolated profile.

## Remaining release work

- Actual Windows 10 22H2 x64 shell/install acceptance, monitor hotplug, virtual desktops and actual OS date rollover remain manual. See [compatibility report](WINDOWS-COMPATIBILITY.md).
- Listen to all new tones on the target Windows audio device; validate the user's OGG encoding (Vorbis support is present, arbitrary OGG codecs are not promised), silent mode and custom-file usability. WAV/MP3 decoder paths were tested at zero volume.
- No PDF edition currently has verified redistribution evidence recorded. Unverified entries remain metadata/cached access; public downloads require permission. Optional OPDS fetching is not implemented; explicit JSON build manifests and local imports use the unified library.
- Complete reserved-rights Adhan permission and version-pinned vendor/content notices before public distribution. Preserve bundled font notices. No rights clearance is implied by this feature freeze.
- The local installer remains unsigned. Use trusted Authenticode signing before public production distribution; no certificate was available during this audit. No automatic Sahib updater exists; WebView2 runtime updates do not update Sahib.
